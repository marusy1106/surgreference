# 1. Структура MVP

## 1.1. Цель MVP

Проверить на первых **100 подтверждённых пользователях**, что студенты и ординаторы:

1. регистрируются и доходят до первого пройденного теста (активация);
2. возвращаются (retention D7 ≥ 25 %, D30 ≥ 15 % — целевые ориентиры, уточняются после первых недель);
3. считают разборы ошибок и кейсы полезными (обратная связь, оценка экрана результата).

Всё, что не помогает проверить эти гипотезы, переносится за MVP.

## 1.2. Аудитория и роли

| Роль | Кто | Что делает |
|------|-----|-----------|
| Пользователь | студент, ординатор, аспирант, врач | учится, проходит тесты и кейсы, смотрит прогресс, участвует в рейтингах (по желанию) |
| Автор контента | преподаватель, ординатор-автор | создаёт черновики уроков, вопросов, кейсов |
| Медицинский рецензент | врач с профильной квалификацией | проверяет и одобряет/возвращает контент |
| Главный редактор | руководитель медицинской редакции | публикует одобренное, управляет дисциплинами, источниками и КР |
| Поддержка | оператор | обратная связь, жалобы на ошибки в контенте, запросы субъектов ПД |
| Аналитик | продукт/основатель | только чтение агрегированной аналитики |
| Суперадминистратор | 1–2 человека | роли, feature flags, тарифы, настройки безопасности |

**Образовательный статус** (студент / ординатор / аспирант / врач + вуз, факультет, специальность, курс) и **уровень знаний** (XP, уровень, освоение по дисциплинам) хранятся и отображаются раздельно: ординатор может иметь 2-й уровень, а студент 3-го курса — 15-й.

## 1.3. Границы MVP

### Входит

| Модуль | Состав MVP |
|--------|-----------|
| Аккаунт | регистрация по email с кодом подтверждения, вход, выход, восстановление пароля, список активных сессий и их отзыв, смена пароля и email, удаление аккаунта, выгрузка своих данных |
| Образовательный профиль | статус, вуз из справочника, факультет, специальность, курс/год ординатуры; смена статуса с историей; заявка «моего вуза нет в списке» |
| Каталог | дисциплины → темы → уроки; поиск по названию; отметка «пройдено» |
| Урок | структурированный текст (заголовки, списки, таблицы, изображения, «важно», ссылки на КР и коды МКБ-10), источники, дата обновления, рецензент |
| Справочники | МКБ-10 (поиск по коду и названию), реестр клинических рекомендаций (версии, статус «действует/пересмотрена», ссылка на первоисточник) |
| Тесты | одиночный и множественный выбор; режимы «по теме» (фиксированный набор) и «тренировка» (случайные вопросы дисциплины); разбор каждого варианта ответа после завершения |
| Клинические кейсы | пошаговый синтетический кейс с точками решения, обратной связью на каждый выбор и итоговым разбором |
| Прогресс | XP, уровень, серия дней, пройденные уроки/тесты/кейсы, освоение по дисциплинам, график активности неделя/месяц/год |
| Геймификация | XP-журнал, уровни, ~15 достижений, серия дней |
| Рейтинги | добровольные: среди студентов (общий и внутри вуза), между вузами; периоды неделя/месяц/всё время |
| Обратная связь | «сообщить об ошибке в контенте» с любого урока/вопроса, общий отзыв, оценка приложения |
| Админка | Django Admin: контент и редакционный процесс, справочники, пользователи (без доступа к паролям), feature flags, тарифы, журнал безопасности, **панель аналитики** |
| Оформление | светлая и тёмная темы, системная по умолчанию; базовая доступность |

### Не входит в MVP (заложено в модели, но не реализуется)

- платёжные SDK, оплата, пробные периоды (только сущности — см. [07-monetization.md](07-monetization.md));
- подтверждение принадлежности к вузу (поля и таблица доменов вузов есть, процесса нет);
- push-уведомления, офлайн-режим целиком (кешируется только каталог и открытые уроки);
- видео-уроки (только изображения), интерактивные 3D/анатомия;
- социальные функции: друзья, комментарии, чаты;
- вход через Сбер ID / VK ID / Apple (возможен позже; если появится сторонний вход на iOS — Apple требует и Sign in with Apple);
- веб-версия для пользователей.

## 1.4. Ключевые пользовательские сценарии

1. **Первый запуск → активация.** Онбординг (3 экрана) → регистрация (email, пароль, никнейм, отдельное согласие на обработку ПД) → код из письма → образовательный профиль (можно пропустить) → выбор 1–3 интересующих дисциплин → предложение пройти первый короткий тест (5 вопросов) → экран результата с разбором и первыми XP.
2. **Ежедневное обучение.** Главная → «Продолжить» (последний урок/тест) → урок → тест по теме → разбор ошибок → XP, серия дней.
3. **Работа над ошибками.** Профиль → Прогресс → дисциплина с низким освоением → тренировка по вопросам, в которых ошибался.
4. **Клинический кейс.** Практика → Кейсы → кейс по дисциплине → последовательные решения → итоговый разбор с оптимальным путём и ссылками на уроки/КР.
5. **Рейтинг.** Рейтинг → предложение участвовать (opt-in, показывается только никнейм) → таблица «Мой вуз / Все студенты / Вузы».
6. **Сменить статус.** Профиль → Образование → «Я окончил вуз, теперь ординатор» → новый статус; история сохраняется, рейтинги вуза считаются по вузу на момент получения XP.
7. **Удалить аккаунт.** Настройки → Удалить аккаунт → подтверждение кодом → сессии отозваны, ПД обезличены (см. [04-auth-security.md](04-auth-security.md#47-удаление-аккаунта-и-запросы-субъектов-пд)).

## 1.5. Экраны MVP

Нижняя навигация из 5 вкладок: **Главная · Каталог · Практика · Рейтинг · Профиль**.

| Вкладка | Экраны |
|---------|--------|
| (до входа) | Онбординг, Регистрация, Код подтверждения, Вход, Восстановление пароля, Образовательный профиль (шаг онбординга) |
| Главная | Приветствие, карточка «Продолжить», карусель «Последний тест / Кейс дня», плитки: серия дней, XP за неделю, освоение, рекомендация темы |
| Каталог | Список дисциплин, Дисциплина (темы), Тема (уроки + тест темы), Урок, Справочник МКБ-10, Реестр КР, Карточка КР, Поиск |
| Практика | Выбор режима, Экран теста, Результат теста с разбором, Список кейсов, Шаг кейса, Итог кейса |
| Рейтинг | Согласие на участие, Студенты (вуз / все), Вузы, период неделя/месяц/всё время |
| Профиль | Профиль, Прогресс и аналитика знаний, Достижения, Образование (статус и история), Настройки (тема, email, пароль, сессии, рейтинг, удаление, выгрузка данных, документы), Обратная связь |

## 1.6. Критерии готовности MVP (Definition of Done)

- Все сценарии 1.4 проходят на реальных iOS- и Android-устройствах на stage-окружении.
- Опубликовано ≥ 3 дисциплин × ≥ 5 тем, ≥ 300 вопросов, ≥ 10 кейсов — каждая единица со статусом «опубликовано» и рецензентом.
- Покрытие тестами backend ≥ 80 % для модулей `accounts`, `assessment`, `gamification`, `billing`; e2e-сценарии регистрации и прохождения теста в CI.
- Пройдены чек-листы MASVS-L1 и ASVS-L2 (см. [04-auth-security.md](04-auth-security.md)), нет открытых уязвимостей уровня High.
- Опубликованы Политика обработки ПД, Пользовательское соглашение, отдельная форма согласия; подано уведомление в Роскомнадзор.
- Панель аналитики показывает все метрики раздела 9 исходного ТЗ на реальных данных stage.
- Восстановление из бэкапа проверено хотя бы один раз.
