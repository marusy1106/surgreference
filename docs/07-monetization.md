# 7. Монетизация: модель с первого дня, платежи — потом

## 7.1. Проверка доступа

Единственная точка принятия решения — `billing.selectors.has_feature(user, key) -> bool` (и `feature_limit(user, key)`):

```python
def has_feature(user, key: str) -> bool:
    if not flags.is_enabled("monetization_enabled"):
        return True                                   # этап 1: всё бесплатно для всех
    if active_grant(user, key):                       # founder / staff / promo
        return True
    plan = effective_plan(user)                       # premium при активной подписке/триале, иначе free
    return plan_has_feature(plan, key)
```

- Результат кешируется в Redis на 5 минут на пользователя, кеш сбрасывается при изменении подписки, гранта или флага.
- Контентные модули помечают единицы `is_premium`; API отдаёт их всегда, но с полем `locked: true` и без тела, если доступа нет, — клиент показывает экран тарифа. На этапе 1 `locked` всегда `false`.
- `GET /app/config` и `GET /me` возвращают `plan`, `entitlements[]`, `monetization_enabled` — клиент не хранит логику тарифов у себя.

## 7.2. Этап 1 — бесплатный запуск

| Что | Состояние |
|-----|-----------|
| `monetization_enabled` | `false` |
| Таблицы `plans`, `features`, `plan_features` | заполнены (Free, Premium) — чтобы проверять логику тестами |
| `store_products`, `subscriptions`, `payment_transactions` | созданы, пустые |
| Платёжные SDK в приложении | **нет** |
| Экраны тарифов | нет (только флаг-заглушка в коде, скрытая) |
| Тесты | матрица «флаг × план × грант × фича» в CI |

## 7.3. Этап 2 — после 100 пользователей (решение, не автоматика)

1. Анализ метрик раздела 6, интервью с пользователями, выбор границы Free/Premium.
2. Предварительный состав:

| Функция | Free | Premium |
|---------|------|---------|
| Справочники МКБ-10 и КР | ✔ | ✔ |
| Уроки | базовые темы каждой дисциплины | весь каталог |
| Тесты | тест темы + 20 тренировочных вопросов в день | без ограничений, «работа над ошибками», расширенные режимы |
| Кейсы | 3 в месяц | все |
| Аналитика знаний | базовая | расширенная |
| Рейтинги, достижения | ✔ | ✔ |

3. Уведомление пользователей **не позже чем за 30 дней** до введения тарифов (письмо + экран в приложении + обновлённое Пользовательское соглашение с новым согласием).
4. **Условия для первых 100:** через `entitlement_grants(reason = founder)` — например, Premium на 6–12 месяцев бесплатно или пожизненная скидка через offer codes магазинов. Конкретный вариант выбирается на этапе 2; модель поддерживает оба.
5. Подключение платежей:
   - iOS — **StoreKit 2**, серверная проверка через App Store Server API и App Store Server Notifications v2 (JWS, проверка подписи).
   - Android/RuStore — актуальный **RuStore Pay SDK**, серверная проверка покупок через API RuStore.
   - Продукты: Premium месяц / год, пробный период 7 дней (introductory offer в App Store; аналог в RuStore).
   - Сервер — единственный источник истины о подписке; одна подписка открывает Premium на всех устройствах и платформах аккаунта.
6. Включение `monetization_enabled` поэтапно через `rollout_percent` и правила флага (сначала только stage и сотрудники).

## 7.4. Feature flags

`feature_flags` редактируются в админке (только `superadmin`, с журналом). Флаг вычисляется на сервере по `enabled`, `rollout_percent` (стабильный хеш от user_id), `rules` (платформа, минимальная версия приложения, группы). Стартовый набор:

| Флаг | Значение на старте |
|------|-------------------|
| `monetization_enabled` | off |
| `leaderboards_enabled` | off до ≥ 20 участников |
| `cases_enabled` | on |
| `registration_captcha` | off (включается при атаке) |
| `certificate_pinning` | on (аварийное отключение) |
| `university_verification` | off |
